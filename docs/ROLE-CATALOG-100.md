\# Role Catalog 100 — Capabilities \& Tasks



A MENU of 100 atomic roles, not an org chart.

Roles are data (`roles/<name>.json`). Divisions / packs / crews are NOT engine entities:

users freely compose any subset of these roles into their own custom division or pack.

The examples below are illustrations of custom composition, NOT fixed presets.



Agent instantiation stays governed by free-tier limits (max\_per\_provider / max\_total\_agents).

The catalog is capability breadth; how many agents run at once is a separate, user-chosen limit.

\## Custom composition (examples, NOT presets)



Users build their own division/pack by picking any subset of roles:

\- \*\*georesearch (example):\*\* GeoResearcher + ClimateAnalyst + WeatherForecaster + GISMapper + HydrologyAnalyst + SeismologyAnalyst + EcologyAnalyst + AgricultureAdvisor + DisasterModeler + EnvironmentalReporter.

\- \*\*asset-management (example, trust-tier):\*\* Bookkeeper + BudgetAnalyst + ExpenseTracker + InvoiceClerk + AssetRegistrar + PortfolioAnalyst + RiskAssessor + FinanceReporter (+ AccessController + AuditLogger for guardrails). Read-only first; human approval per write; never store raw credentials.

These are illustrations. A user may pick 3 roles or 30, mix across the catalog, and name their division whatever they like.



\## Adding a role

Create `roles/<name>.json` (name, persona, capabilities, tools, modules); add module cells to the blueprint; gate + PR. No engine code change. See CONTRIBUTING.
